What this is

A tool for listing and rewriting the text layers of a PSD. It is meant for re-editing text — translation, proofreading, fixing inconsistent wording — without opening Photoshop.

Layers you do not edit are written back byte for byte, so image layers and effects are left completely untouched.

The screen

Left: Layers
The layer structure of the PSD. ▾ folds a group and 👁 toggles visibility; a folder's 👁 applies to everything inside it. These toggles are preview-only and are never saved into the PSD ("Reset" goes back to the visibility stored in the file). Layers marked T are text layers, and ● means there are unsaved changes. The "List" toggles above narrow down what is listed at all — a different thing from visibility (text / unsaved / currently shown). The search box at the top matches layer names and body text.
Centre: Preview
The composite of everything currently visible. 100% is true 1:1 (one image pixel per physical screen pixel) — it does not double in size on a display running at 200% scaling. "Fit" scales it to the window.
Right: Edit
Position, formatting and body of the selected text layer. The body carries a ◆ chip (formatting mark) wherever the formatting changes, and the panel above edits the mark the caret belongs to. Changes to the text itself reach the document when you press Apply; changes made in the formatting panel are applied immediately.

Basic flow

  1. Open… and pick a PSD — dropping a PSD onto psdtext.exe (or a shortcut to it) opens it too, as does psdtext foo.psd. The dialog starts in the folder you used last
  2. Select a text layer in the tree on the left
  3. Rewrite the body in the pane on the right
  4. Apply (Ctrl+Enter) to put it into the document
  5. Save (Ctrl+S) to write the file

"Apply" only changes the document held in memory. The file is written when you press "Save". The counter at the top shows how many layers have been applied but not yet saved.

Formatting (marks)

Formatting is expressed with marks. A mark says "change the formatting from here on", and sits in the body as a ◆ chip. Tags never appear in the edit box (they are how CSV and the file itself carry the same information).

What you edit is the mark the caret belongs to. Put the caret anywhere in the body and the mark in effect there is selected, with the panel above showing its formatting. With no mark before the caret you are on the base, and changing it changes everything that has no explicit formatting.

Base (before any mark)
The initial formatting of the whole layer. Font, size, colour, B/I/U and alignment are simply chosen, and they apply to everything that has no explicit formatting — which is all most edits ("make this layer bigger / another colour") ever need. A change to the base is not shown as a chip, since the start of the body is always the base.
Marks in the body
Click a chip (or put the caret after it) to edit that mark attribute by attribute, each one set to keep / back to base / set. An attribute left at "keep" simply carries on from whatever came before. Remove mark, or Backspace over the chip, takes it out entirely — a chip behaves like a single character.
＋Mark
Puts a new mark at the caret. It is committed as soon as you set something on it.
Formatting a range
Select a range in the edit box and the panel switches to editing that selection. What you set is inserted at the start of the range, and a mark that restores the previous formatting is placed at the end. Nothing is ever "closed", so it cannot break whatever formatting the surrounding text had.

Choosing a font
On the base you simply pick one from the list. On a mark or a range you press the font button and choose from the list, which shows "fonts this PSD uses" first and "fonts on this PC" below. The base's ＋ opens the same list. Photoshop needs the same font as well; without it Photoshop substitutes another one.

Changes made in the formatting panel go into the document straight away (the preview follows immediately). "Apply" is only for text you typed. Either way, "Revert" takes the layer back to how it was loaded.

Formatting tags

Marks are really just tags embedded in the body. The edit box hides them, but the text column of a CSV carries this form — so this is the notation to use when editing formatting in bulk in a spreadsheet. 

This is [b]bold[/b] and [size=96]large[size=48]text
[color=#FF0000]red text[color=#000000]back to black
[font=NotoSansJP-Bold]another font[/font]back to the base font
[align=center]a centred paragraph

There are no closing tags. A tag changes the state from that point onward and stays in effect until the next one. To go back, either specify a value again or use [/xxx]. PSD runs are a flat sequence rather than a nested structure, so this form maps directly onto it — and there is no nesting for a translator to accidentally break.

The base is the style of the first run as the file was loaded, and it never moves as you edit: [/color] always means "the colour this file had when it was opened". Changing the initial formatting means laying a mark over that base — which is why "Revert" can always get you back.

Tags only appear where the style differs from the base. Uniformly styled text therefore carries no tags at all, so ordinary translation work never has to deal with them.

Tags that cannot be understood are kept as plain characters, so the body is never lost. Anything that could not be interpreted is reported under the edit box.

Working with layers

Selecting several layers
Ctrl+click adds or removes a layer, Shift+click takes a range. With two or more selected, the right pane turns into bulk operations.
  • Initial formatting for all of them — font / size / colour / B·I·U / alignment. Marks placed inside a body are left alone
  • Copy formatting → Paste — remembers the initial formatting of the layer you selected last and applies it to every selected layer
  • Duplicate… — copies them with a prefix / suffix on the name (en_ and so on). The layer mask is duplicated too, which is what makes this usable as groundwork for another language. The copies stay selected, so a bulk font change follows naturally
  • Export these — writes only the selected layers to CSV
Renaming
Double-click the name in the tree, or select the layer and press F2 (the "Rename" button does the same). Enter commits, Esc cancels. Works on any layer, not just text.
Duplicate (= adding a layer)
Duplicates the selected text layer. The dialog lets you set the name and the body on the spot, so rewriting the body makes this, in effect, "add a new text layer" — which is why there is no separate button for it.
  • Font, size, colour, position and text box are inherited from the source (move it in Photoshop if you need a different position)
  • Because it is built from an existing layer rather than from scratch, a PSD with no text layer at all cannot get one
Text position and box
"Position" and "Box" on the right take numbers, and you can also:
  • Drag on the preview — grab inside the rectangle of the selected text layer
  • Arrow keys for 1px, Shift+arrow for 10px (when the cursor is not in a field)
"Position" is in document coordinates and "Box" is the size of the text box. Resizing the box only reflows paragraph text; for point text Photoshop rebuilds the box from the glyphs. Moving a layer moves the raster stored in the PSD along with it, so nothing looks displaced before Photoshop reopens the file.
Reordering (▲▼)
Moves the layer up or down within its own level. Selecting a folder moves it together with its contents. Moving across levels (in and out of folders) is not supported — do that in Photoshop. At either end you get "cannot move any further".

Bulk editing with CSV

Export CSV produces a file in this shape (UTF-8 with BOM and CRLF, so Excel opens it directly): 

lyid,path,text
2,"dialog/name","Hello"
4,"dialog/body","first line
second line"
  • A newline inside the text cell becomes a paragraph break
  • The text column may contain formatting tags
  • Layers are matched by lyid (Photoshop's persistent layer ID), so reordering or renaming layers does not break the mapping. Rows without an lyid fall back to the path column (reported as unresolved when several layers share that name)
  • Column order is free and extra columns are ignored

Import CSV first performs a check only pass and reports how many rows would change, stay identical, or fail to resolve. Press "Apply" once the report looks right (that puts it into the in-memory document — the file is written by "Save"). A CSV can also be dropped onto the window.

Where it goes
Exports land next to the PSD as <name>_texts.csv by default, and the import dialog starts from that same path — no hunting for the file. Use "Download instead" to receive it through the browser.
Encoding
Exports are UTF-8 with a BOM. Imports also accept the Shift-JIS file Excel saves by default; the report says which one it read.
When "Apply" stays disabled
It needs at least one row that differs. The reason (nothing differs / no row matched a layer) is written under the report. A CSV exported from a different PSD shows up as "unresolved" because the lyid values do not match.

How saving works

  • Saving over the original keeps it as <name>.psd.bak (an existing .bak is never overwritten)
  • Entering a path in the save dialog saves under that name and continues editing there
  • Layers you did not edit are written back byte for byte
  • Visibility toggles are preview-only and are not saved

What it cannot do (limits of the preview)

The preview in the centre is an approximate composite for working purposes and does not match what Photoshop draws. Always confirm the result in Photoshop.

Compositing

  • Adjustment layers (curves, hue/saturation, …) are not applied
  • Layer effects (drop shadow, glow, stroke, …) are not applied
  • Blend mode and opacity of groups (folders) are not applied
  • Blend modes the browser has no equivalent for (vivid light, linear light, pin light, linear burn, …) are approximated with the closest available mode
  • Vector masks are not supported (layer masks are)

Redrawn text

The text raster stored in the PSD is not updated until Photoshop reopens the file, so edited text layers are redrawn by the browser instead. That is also an approximation:

  • Kerning, tracking and line-breaking rules are not reproduced
  • Vertical text is drawn horizontally
  • Transforms (rotation, scaling, warp) are not applied
  • Line spacing is estimated as "largest font size × 1.4"
  • Text is not wrapped to the box (long text overflows it)
  • Fonts not installed on this PC are substituted (noted in the edit pane)

Editing

  • Adding a text layer is built on duplicating an existing one (see "Duplicate"), so a PSD without a single text layer cannot get one
  • Position and text box can be changed for text layers only. Moving or scaling image layers is done in Photoshop
  • Text cannot be rotated or transformed (only the translation part of the matrix is handled)
  • Reordering is limited to one level; layers cannot be moved in or out of folders
  • The composite thumbnail Photoshop stores in the file stays stale after saving

Automation (REPL)

The app can be driven through --repl (interactive), --replfile=DIR (agents / CI) or POST /_app/repl (curl).

.psdInformation about the open document
.textsList the text layers (* = unsaved)
.settext <index> <text>Replace a body
.b stateInspect the UI state
.b call select 3Select a layer
.b call rename {"index":1,"name":"New"}Rename a layer
.b call move {"index":3,"up":true}Change the stacking order
.b call place {"x":200,"y":120}Text position
.b call place {"width":320,"height":180}Text box
.b call lang enSwitch the display language
.b call saveSave

See the README for the full HTTP API. Every route requires the X-App-Token header.
